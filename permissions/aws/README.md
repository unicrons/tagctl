# IAM roles for tagctl

tagctl needs an IAM role in every AWS account it touches. Pick one by what you
want to do:

| I want to... | Deploy | Commands |
|--------------|--------|----------|
| Audit tags only | [`TagctlScan`](tagctl-scan-role.yaml) | `scan`, `plan`, `diff`, `normalize`, `terraform`, `cost` |
| Also fix tags | [`TagctlApply`](tagctl-apply-role.yaml) | everything above plus `apply` |

`TagctlScan` is read-only: it cannot write a tag, so it is safe for a scheduled
job or an auditor. `TagctlApply` adds the tag write actions; assume it
deliberately, ideally with MFA or an external id. Then point `role_arn` in
`tagctl.yaml` at the role.

## Files

| File | What it is |
|------|------------|
| `tagctl-scan-policy.json`, `tagctl-apply-policy.json`, `tagctl-apply-codebuild-policy.json` | The policy documents, the source of truth. Use them with Terraform (`file()`), the console or an existing role. |
| `tagctl-scan-role.yaml`, `tagctl-apply-role.yaml` | CloudFormation templates that embed those policies verbatim. Generated by `scripts/render-iam-templates.py` (`make iam-templates`): edit the JSON, not the YAML. |

## Deploy

```bash
# read-only, trusted by the whole account
aws cloudformation deploy \
  --template-file tagctl-scan-role.yaml \
  --stack-name tagctl-scan-role \
  --capabilities CAPABILITY_NAMED_IAM \
  --parameter-overrides TrustedPrincipalArn=arn:aws:iam::111111111111:root

# read-write, trusted by one role in another account, MFA required
aws cloudformation deploy \
  --template-file tagctl-apply-role.yaml \
  --stack-name tagctl-apply-role \
  --capabilities CAPABILITY_NAMED_IAM \
  --parameter-overrides \
    TrustedPrincipalArn=arn:aws:iam::222222222222:role/platform-admin \
    ExternalId=4f2c9a \
    RequireMFA=true \
    ProtectedTagKeys=access-team,access-level
```

The `TagctlConfig` output is the account entry to paste under `clouds.aws`.

## Parameters

Only `TrustedPrincipalArn` is required. Everything else narrows who may assume
the role or what it may do.

| Parameter | Default | Notes |
|-----------|---------|-------|
| `TrustedPrincipalArn` | required | Account root, IAM role/user or Identity Center permission-set role. |
| `ExternalId` | empty | Enforced as `sts:ExternalId` when set; mirror it in `external_id`. |
| `RequireMFA` | scan `false`, apply `true` | Adds `aws:MultiFactorAuthPresent`. Keep `false` for CI. |
| `OrgId` | empty | Adds `aws:PrincipalOrgID`: the caller must also belong to this organization. It narrows `TrustedPrincipalArn`, it does not replace it. |
| `RoleName` | `TagctlScan` / `TagctlApply` | |
| `MaxSessionDuration` | `3600` | Ceiling for `session_duration`; raise it for large accounts. |
| `PermissionsBoundaryArn` | empty | |
| `AllowCodeBuildTagging` | `false` (apply only) | Attaches `TagctlApplyCodeBuild`. See [CodeBuild](#codebuild). |
| `ProtectedTagKeys` | empty (apply only) | Comma-separated tag keys, wildcards allowed, no spaces around the commas. Attaches `TagctlProtectedTagKeys`. See [Protected tag keys](#protected-tag-keys). |

## Design notes

Background on the choices in the policies. You do not need it to deploy.

### Scope

- **Scan** stays on `"*"` because it only reads. `ce:GetCostAndUsage` is there
  for `tagctl cost` and nothing else.
- **Apply** limits every write action to the ARN patterns of the resource types
  tagctl tags, taken from the
  [Service Authorization Reference](https://docs.aws.amazon.com/service-authorization/latest/reference/reference_policies_actions-resources-contextkeys.html).
- **Partition:** the ARNs use `aws`. In AWS China or GovCloud, replace
  `arn:aws:`.
- **Size:** IAM caps a role's inline policies at 10,240 characters (whitespace
  excluded). Scan, apply and CodeBuild use about 9,150, leaving about 900 for
  the `ProtectedTagKeys` list.

### Exceptions to the scoping

| Action | Scope | Why |
|--------|-------|-----|
| `tag:TagResources`, `workspaces:CreateTags` | `"*"` | The reference lists no resource type for them. `tag:TagResources` still needs the scoped action of the service that owns the resource. |
| `apigateway:PUT`, `POST` | `/tags/*` only | Tagging REST and HTTP/WebSocket APIs uses them, and the path limit stops them from creating, updating or importing an API. |

Two things are unverified:

- HTTP API tagging through `POST`: the reference lists the `Tags` resource type
  under `PUT` but not `POST`.
- Service Catalog portfolios: the policy does not grant `servicecatalog:TagResource`
  (the reference maps it only to AppRegistry resources, which tagctl never tags)
  or `servicecatalog:UpdatePortfolio`. Which action `tag:TagResources` checks
  for a portfolio is not documented, so portfolios may not be taggable.

### CodeBuild

CodeBuild has no tag-only IAM action. Project tags are written with
`codebuild:UpdateProject`, which can also replace a project's buildspec and
service role, so it is off by default.

Until you set `AllowCodeBuildTagging=true`, `tagctl apply` reports CodeBuild
changes as failed.

### Protected tag keys

`ProtectedTagKeys` denies any request whose `aws:TagKeys` match one of the
listed keys (`ForAnyValue:StringLike`). Use it for the keys your ABAC policies
check.

It has two gaps:

- **Some actions are not covered.** The deny only works on actions whose
  reference entry lists `aws:TagKeys`. `s3:PutBucketTagging`,
  `route53:ChangeTagsForResource` and `glacier:AddTagsToVault` do not, so
  bucket, hosted zone and vault tags are not protected.
- **Case matters.** `StringLike` is case-sensitive, but IAM user and role tag
  keys are not: `iam:TagRole` with `Access-Team` overwrites `access-team`
  without matching `ProtectedTagKeys=access-team`. List the case variants, or
  use `?` for letters that may vary (`?ccess-?eam`).
