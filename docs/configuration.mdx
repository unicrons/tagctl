tagctl is configured via a YAML file (default: `tagctl.yaml`).

## File Location

tagctl looks for configuration in this order:

1. Path specified with `--config` flag
2. `tagctl.yaml` in the current directory
3. `~/.tagctl/tagctl.yaml`

A file passed with `--config` must exist. When no file is found, `scan`, `plan`
and the other commands that read the configuration run with an empty one
(`scan` falls back to demo mode), `evaluate` needs `--policy` and `validate`
fails.

## Complete Example

```yaml
# Cloud provider configuration
clouds:
  aws:
    - profile: production
      regions: [us-east-1, eu-west-1]
    - profile: staging
      regions: [us-east-1]

# Tag policy definition
policy:
  required:
    - name: environment
      description: Deployment environment
      values: [dev, staging, prod]
    - name: cost-center
      pattern: "^[A-Z]{2,4}-\\d{3,6}$"
    - name: owner
      pattern: "^.+@company\\.com$"
  optional:
    - name: project
    - name: team

# Auto-fix rules
rules:
  infer:
    - tag: environment
      from_name:
        - pattern: "-prod-"
          value: prod
        - pattern: "-staging-|-stg-"
          value: staging
        - pattern: "-dev-"
          value: dev


  defaults:
    - resource: "*"
      when:
        tag:owner: absent
      set:
        owner: platform-team@company.com
        needs-review: "true"

# Resources to ignore
ignore:
  resources:
    - "aws_cloudwatch_*"
    - "aws_iam_*"
  tags:
    managed-by: [terraform, pulumi]
```

### AWS Configuration

`clouds.aws` is a **list** of accounts. Each entry is one account, identified by
a profile, by a role to assume, or by nothing at all (the SDK default chain:
environment variables, SSO session, instance role). Keys are never read from
this file.

```yaml
clouds:
  aws:
    - profile: production
      # Omit regions to scan all available regions
    - profile: staging
      regions: [us-east-1]  # Or specify specific regions
    - regions: [eu-west-1]  # No profile: credentials from the environment
    - profile: audit-base
      role_arn: arn:aws:iam::111111111111:role/TagctlScan
```

<ParamField path="profile" type="string">
  AWS profile from `~/.aws/config` / `~/.aws/credentials`. Omit it to use the
  SDK default chain. Only one entry may omit both `profile` and `role_arn`,
  since the default chain identifies a single account.
</ParamField>

<ParamField path="role_arn" type="string">
  IAM role to assume with the resolved credentials. `external_id`,
  `session_duration` (900–43200, default 3600), `role_session_name` (default
  `tagctl`) and `mfa_serial` (TOTP code read from stdin) refine it and require
  it. See [Assuming Roles](/credentials#assuming-roles).
</ParamField>

<ParamField path="regions" type="string[]">
  Regions to scan. If omitted, all available regions are discovered and scanned.
  Applies to every service, S3 included: buckets outside these regions are not
  read. Region codes are validated (`eu-west1` is rejected).
</ParamField>

<Warning>
Write `aws:` as a list (`- profile:` / `- regions:`). A mapping (`aws:` followed by
`regions:` directly) happens to decode as one account today, but `tagctl validate`
warns about it because it breaks as soon as a second account is added.
</Warning>

## Section: `policy`

Defines tag requirements for compliance.

### Required Tags

Tags that **must** be present on all resources:

```yaml
policy:
  required:
    # Enum-based validation
    - name: environment
      description: Deployment environment
      values: [dev, staging, prod]

    # Pattern-based validation
    - name: cost-center
      description: Finance cost code
      pattern: "^[A-Z]{2,4}-\\d{3,6}$"

    # Email pattern
    - name: owner
      pattern: "^.+@.+$"
```

<ParamField path="name" type="string" required>
  Tag key name
</ParamField>

<ParamField path="description" type="string">
  Human-readable description
</ParamField>

<ParamField path="values" type="string[]">
  Allowed values (enum). Checked before `pattern`; a value outside the list is
  reported as `invalid_value`.
</ParamField>

<ParamField path="pattern" type="string">
  Regex pattern for validation, reported as `invalid_format`. Both can be set
  on the same tag; the value must then satisfy both.
</ParamField>

### Optional Tags

Tags that are tracked but not required:

```yaml
policy:
  optional:
    - name: project
    - name: team
    - name: application
```

An optional tag is checked only on resources that carry it. There, a value
outside `values` or not matching `pattern` fails the same way a required tag
does; a resource without the tag gets no finding for it. In the scan's `by_tag`
statistics an optional tag counts only the resources that carry it: `missing`
stays 0 and `compliance_percent` is the share of those values that are valid
(100 when no resource carries the tag).

## Section: `rules`

Defines auto-fix rules for the `plan` command. See [Rules Documentation](/rules) for details.

### Infer Rules

Derive tag values from resource naming conventions:

```yaml
rules:
  infer:
    - tag: environment
      from_name:
        - pattern: "-prod-"
          value: prod
        - pattern: "-staging-"
          value: staging
```

### Inherit Rules

`rules.inherit` is parsed and counted by `tagctl validate`, but `plan` does
not apply it yet: no parent-child relationship is resolved during discovery.
Leave it out until inheritance ships.

### Default Rules

Apply default values when tags are missing:

```yaml
rules:
  defaults:
    - resource: "*"
      when:
        tag:owner: absent
      set:
        owner: platform-team@company.com
```

`resource` (a glob, see [By Resource Type](#by-resource-type)) and at least one
`set` entry are required. Every `when` condition must hold: a `tag:<name>` key
with `absent` or the exact value the tag must have. Tag names keep their case
(`tag:CostCenter` and `tag:costcenter` are different tags). See
[Conditions](/rules#conditions).

## Section: `ignore`

Exclude resources from scanning.

### By Resource Type

```yaml
ignore:
  resources:
    - "aws_iam_*"
    - "aws_cloudwatch_*"
```

Patterns match the resource **type** with Go `path.Match` syntax: `*` matches
any run of characters, `?` a single character and `[...]` a character class,
anywhere in the pattern (`aws_iam_*`, `*_group`, `aws_*_group`). A malformed
pattern such as `aws_[` is rejected when the config loads.

### By Tag Value

```yaml
ignore:
  tags:
    managed-by: [terraform, pulumi, cloudformation]
    status: [deprecated, deleting]
```

Tag keys and values are compared exactly, case included: `ManagedBy` does not
match a `managedby` tag.

## Environment Variables

Values in the file are **not** expanded: `${AWS_ACCESS_KEY_ID}` is passed to AWS
literally. To use credentials from the environment, omit `profile` and the keys
and let the SDK default chain pick them up:

```bash
export AWS_ACCESS_KEY_ID=AKIA...
export AWS_SECRET_ACCESS_KEY=...
```

```yaml
clouds:
  aws:
    - regions: [us-east-1]
```

## Validation

Always validate your configuration before running:

```bash
tagctl validate
```

`validate` reports the configuration summary plus every problem the commands
would hit. The checks below run at the start of every command that loads a
config file (`scan`, `plan`, `apply`, `evaluate` with or without `--policy`,
...), so a broken file is rejected before any cloud API is called:

- YAML syntax and structure: a key outside the schema (`polcy:`, `valuse:`) is
  an error that names its line
- Account shape: no static keys, role options only with `role_arn`, at most one
  entry relying on the SDK default chain
- Region codes (`eu-west1`, `EU-WEST-1` and duplicates are rejected)
- Tag requirements: `name` present in `policy.required` and `policy.optional`,
  no tag defined twice across both, regex patterns in `pattern` and
  `rules.infer[].from_name[].pattern` compile
- Default rules: `resource` present, `set` not empty, `when` conditions written
  as `tag:<name>` with `absent` or an exact value
- Glob patterns in `rules.defaults[].resource` and `ignore.resources`
- Kubernetes cluster names (required, unique) and `resource_types` (unknown or
  repeated types are rejected)

`tagctl validate` is stricter than the commands: it also fails on a file with
no cloud account or no tag policy, and warns about unknown providers, a
provider key with no accounts, a policy with no required tags and `clouds.aws`
written as a mapping. `scan` itself runs in demo mode without a provider and
`evaluate` works from a JSON file.
