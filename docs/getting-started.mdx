## Prerequisites

- **Go 1.26.6+** (for `go install` and building from source)
- **AWS credentials** configured

## Installation

`go install` and building from source work today. The binaries, the container
image and the Homebrew cask are published by the release pipeline: they exist
after the first release is tagged, and
[GitHub Releases](https://github.com/unicrons/tagctl/releases) shows whether
that has happened.

<Tabs>
  <Tab title="Go Install">
    ```bash
    go install github.com/unicrons/tagctl/cmd/tagctl@latest
    ```
    The binary reports version `dev`: only release builds are stamped.
  </Tab>
  <Tab title="Build from Source">
    ```bash
    git clone https://github.com/unicrons/tagctl.git
    cd tagctl
    make build
    ```
    The binary will be at `./bin/tagctl`.
  </Tab>
  <Tab title="Download Binary">
    Available after the first release. Each release carries one archive per
    platform, `tagctl_<os>_<arch>.tar.gz` (`.zip` on Windows) for `linux`,
    `darwin` and `windows` on `amd64` and `arm64`, and a `checksums.txt`:

    ```bash
    curl -fsSLO https://github.com/unicrons/tagctl/releases/latest/download/tagctl_linux_amd64.tar.gz
    curl -fsSLO https://github.com/unicrons/tagctl/releases/latest/download/checksums.txt
    sha256sum --check --ignore-missing checksums.txt
    tar -xzf tagctl_linux_amd64.tar.gz tagctl
    sudo install tagctl /usr/local/bin/tagctl
    ```

    On macOS use `shasum -a 256 --check --ignore-missing checksums.txt`. The
    binaries are not notarized: an archive downloaded with a browser is
    quarantined, so run `xattr -d com.apple.quarantine tagctl` once before the
    first run.
  </Tab>
  <Tab title="Container">
    Available after the first release, for `linux/amd64` and `linux/arm64`:

    ```bash
    docker run --rm ghcr.io/unicrons/tagctl version
    ```

    Pin a release with its tag (`ghcr.io/unicrons/tagctl:v0.1.0`). The image
    runs as a non-root user and has no shell. Mount the directory that holds
    `tagctl.yaml` as the working directory, where `output/` is written too,
    and pass credentials through the environment:

    ```bash
    docker run --rm \
      -v "$PWD:/work" -w /work --user "$(id -u):$(id -g)" \
      -e AWS_ACCESS_KEY_ID -e AWS_SECRET_ACCESS_KEY -e AWS_SESSION_TOKEN \
      ghcr.io/unicrons/tagctl scan
    ```
  </Tab>
  <Tab title="Homebrew">
    Available once the `unicrons/homebrew-tap` repository is published, which
    happens after the first release (macOS and Linux):

    ```bash
    brew install --cask unicrons/tap/tagctl
    ```
  </Tab>
</Tabs>

## Your First Scan

<Steps>
  <Step title="Initialize Configuration">
    ```bash
    tagctl init
    ```
    This creates `tagctl.yaml` with a template configuration.
  </Step>

  <Step title="Configure Cloud Access">
    Edit `tagctl.yaml` to point to your cloud accounts:

    <CodeGroup>
    ```yaml AWS (all regions)
    clouds:
      aws:
        - profile: default
          # regions not specified = scan all available regions
    ```

    ```yaml AWS (specific regions)
    clouds:
      aws:
        - profile: default
          regions:
            - us-east-1
            - eu-west-1
    ```
    </CodeGroup>

    Verify your credentials:
    ```bash
    aws sts get-caller-identity
    ```

    <Tip>
    Prefer a dedicated role over your own credentials. The repository ships a
    read-only `TagctlScan` role as a CloudFormation template; deploy it and add
    `role_arn` to the entry. See [Scan role vs apply role](/credentials#scan-role-vs-apply-role).
    </Tip>
  </Step>

  <Step title="Define Your Tag Policy">
    Edit the `policy` section to define required tags:

    ```yaml
    policy:
      required:
        # Environment must be one of these values
        - name: environment
          description: Deployment environment
          values: [dev, staging, prod]

        # Cost center must match this pattern
        - name: cost-center
          description: Finance cost allocation code
          pattern: "^[A-Z]{2,4}-\\d{3,6}$"

        # Owner must be an email
        - name: owner
          description: Team or person responsible
          pattern: "^.+@.+$"
    ```
  </Step>

  <Step title="Validate Configuration">
    ```bash
    tagctl validate
    ```

    <Accordion title="Expected output">
    ```
    Validating tagctl.yaml...

    ✓ Cloud providers configured: 1
    ✓ Required tags defined: 3
    ✓ Optional tags defined: 0
    ✓ Auto-fix rules defined: 2
    ✓ Ignore rules defined: 2

    Configuration is valid!
    ```
    </Accordion>
  </Step>

  <Step title="Scan Your Resources">
    ```bash
    tagctl scan
    ```

    You'll see a compliance report showing:
    - Overall compliance percentage
    - Compliance by account
    - Compliance by tag (with PASS/FAILED status)
    - List of specific findings

    Reports are automatically saved to `output/`:
    - `scan-TIMESTAMP.json` - Full results with all findings
    - `scan-TIMESTAMP.csv` - All findings for spreadsheets
    - `scan-TIMESTAMP.html` - Visual report for sharing
  </Step>

  <Step title="Generate a Fix Plan">
    ```bash
    tagctl plan
    ```

    This reads the latest scan results and generates fixes using:
    - **Inference**: Derive tags from resource names
    - **Defaults**: Apply default values

    The plan is saved to `output/plan-TIMESTAMP.json`.

    <Tip>
    You can specify a different scan file with `--scan`:
    ```bash
    tagctl plan --scan output/scan-20260202-143052.json
    ```
    </Tip>
  </Step>

  <Step title="Review and Apply">
    Review the plan, then apply:
    ```bash
    tagctl apply
    ```
    You'll be asked to confirm before any changes are made.

    <Note>
    `apply` is the only command that writes. With the shipped roles, the scan
    role cannot do it: pass the apply role for this run only,
    `tagctl apply --role arn:aws:iam::111111111111:role/TagctlApply`.
    </Note>

    <Tip>
    You can specify a different plan file with `--plan`:
    ```bash
    tagctl apply --plan output/plan-20260202-143052.json
    ```
    </Tip>
  </Step>
</Steps>

## Troubleshooting

Use debug logging for detailed trace:
```bash
tagctl scan --log-level debug
```

<AccordionGroup>
  <Accordion title="No config file found">
    Make sure `tagctl.yaml` exists in your current directory, or specify it:
    ```bash
    tagctl scan --config /path/to/tagctl.yaml
    ```
  </Accordion>

  <Accordion title="AWS Authentication Errors">
    Verify your credentials:
    ```bash
    aws sts get-caller-identity --profile your-profile
    ```
    Make sure the profile name in `tagctl.yaml` (or `--profile`) matches. Keys
    are never read from the file: put them in `~/.aws/credentials` or export
    them.
  </Accordion>

  <Accordion title="Scanning the wrong regions">
    The regions to scan never come from the AWS profile or `AWS_REGION`: set
    `regions` in `tagctl.yaml` or pass `--region`; leave the list empty to
    discover every region through `ec2:DescribeRegions`.
  </Accordion>

  <Accordion title="No resources found">
    Check that:
    1. The regions/namespaces in your config contain resources
    2. Your credentials have read permissions
    3. Resource types aren't excluded in the `ignore` section

    Use debug logging to see exactly what's scanned:
    ```bash
    tagctl scan --log-level debug --region us-east-1
    ```
  </Accordion>
</AccordionGroup>
