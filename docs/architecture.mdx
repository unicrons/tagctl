### Engine Layer

Core business logic, abstracted behind interfaces.

```go
// Scanner discovers resources and checks compliance
type Scanner interface {
    Scan(ctx context.Context) (*types.ScanResult, error)
}

// Evaluator evaluates resources against policy
type Evaluator struct {
    policy   config.PolicyConfig
    compiled map[string]*regexp.Regexp
}

// Applier applies tag changes
type Applier interface {
    Apply(ctx context.Context, plan *types.Plan) (*ApplyResult, error)
}
```

### Provider Layer

Abstracts cloud-specific operations.

```go
type Provider interface {
    Name() string
    ListResources(ctx context.Context) ([]types.Resource, error)
    ApplyTags(ctx context.Context, resourceID string, tags map[string]string) error
}
```

## Data Flow

Commands pass data via JSON files in the `output/` directory:

```
tagctl scan  ──▶  output/scan-TIMESTAMP.json
                          │
tagctl plan  ◀────────────┘
      │
      └──────▶  output/plan-TIMESTAMP.json
                          │
tagctl apply ◀────────────┘
```

<Steps>
  <Step title="Scan → output/scan-*.json">
    1. Load configuration (`tagctl.yaml`)
    2. Initialize AWS provider with credentials
    3. Call `ListResources()` - runs every service lister in every region
    4. Pass resources to Evaluator
    5. Generate **Findings** (PASS/FAILED) for each resource+tag
    6. Write results to `output/scan-TIMESTAMP.json`
    7. Also write CSV and HTML reports
  </Step>

  <Step title="Plan → output/plan-*.json">
    1. Load scan results (latest or specified with `--scan`)
    2. Apply inference rules (extract tags from resource names)
    3. Apply default rules (fallback values)
    4. Generate `Plan` with proposed changes
    5. Write plan to `output/plan-TIMESTAMP.json`
  </Step>

  <Step title="Apply">
    1. Load plan file (latest or specified with `--plan`)
    2. Show summary and ask for confirmation
    3. Group changes by resource and region
    4. Call `ApplyTags()` on AWS provider
    5. Report success/failure for each change
  </Step>
</Steps>

### Finding

The evaluator generates **Findings** with PASS or FAILED status:

```go
type Finding struct {
    Resource Resource        `json:"resource"`
    Tag      string          `json:"tag"`
    Status   FindingStatus   `json:"status"`   // "PASS" or "FAILED"
    Reason   ViolationReason `json:"reason"`   // "compliant", "missing", etc.
    Expected string          `json:"expected,omitempty"`
    Actual   string          `json:"actual,omitempty"`
}

// FindingStatus values
const (
    StatusPass   FindingStatus = "PASS"
    StatusFailed FindingStatus = "FAILED"
)
```

### Violation (deprecated)

```go
type Violation struct {
    Resource Resource        `json:"resource"`
    Tag      string          `json:"tag"`
    Status   FindingStatus   `json:"status"` // Always "FAILED"

    Expected string          `json:"expected,omitempty"`
    Actual   string          `json:"actual,omitempty"`
```

Use `Findings` instead of `Violations` in new code. Violations are kept for backward compatibility.

## Concurrency

- Providers list resources concurrently per region/namespace
- The AWS provider runs every (region × service) lister in its own goroutine,
  plus one for S3 and one per global lister (Route 53, CloudFront, IAM,
  Shield, WAF Classic global, WAFv2 CloudFront, Global Accelerator)
- Before any lister starts, one `tag:GetResources` sweep per region is launched
  in the background (`internal/provider/aws/tags.go`). Listers block on their
  region's sweep only when they need a tag lookup, so discovery and the bulk
  tag read overlap. Services whose Describe call returns tags inline never wait
- When the sweep fails, services with a per-resource tag API fall back to it
  with a semaphore of 16 concurrent calls; services without one are skipped
- The SDK HTTP client uses a 5s connect timeout, so an unreachable regional
  endpoint costs seconds, not minutes
- Applier processes resources with configurable concurrency, runs its progress
  callback one change at a time and stops dispatching once the context is
  cancelled
- All operations respect context cancellation

```go
// Example from scanner
var wg sync.WaitGroup
for _, p := range s.providers {
    wg.Add(1)
    go func(p provider.Provider) {
        defer wg.Done()
        resources, _ := p.ListResources(ctx)
        // ...
    }(p)
}
wg.Wait()
```

## Error Handling

- A provider that fails discovery does not discard the resources other
  providers returned: the scan is marked `partial`, every provider error is
  joined, and `tagctl scan` writes its reports and then fails unless
  `--allow-partial` is set
- Operations continue when possible
- A resource whose tags cannot be read is skipped with an error, never reported
  as untagged: a network failure must not become a compliance finding. The same
  rule applies to a whole service when it depends on `tag:GetResources` and the
  permission is missing
- Structured errors with provider/operation context

```go
type ProviderError struct {
    Provider   string
    Operation  string
    ResourceID string
    Err        error
}
```
